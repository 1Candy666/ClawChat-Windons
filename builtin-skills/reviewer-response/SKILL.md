# 审稿回复 · Reviewer Response
交流语言跟随用户，回复信默认英文，可按投稿语言调整。默认输出可复制文本；用户明确要求文件时按可用工具制作，不因默认文本交付拒绝文件要求。

## 从意见到可核验回复
1. 保留原意见与编号，拆分复合问题，区分提问、改正、补分析、解释、文献与格式要求。
2. 检查已提供原文、数据和修改记录；内部标记“已完成且可核验”“作者声明已完成但未检查”“拟修改”“有理由不采纳”。已给材料优先使用。
3. 回复直接回答具体问题，再说明采取的动作、依据和位置。简短意见简短答，复杂方法与实质异议提供充分理由，不固定为一句话。必要时如实承认错误，不以省略掩盖实质问题。
4. 无已完成修改的依据时用未来时或明确标为 Proposed response，不写 We have added/completed。仅有全文不代表修订已经完成。作者确认事实后可生成最终措辞。
5. 默认先给 Response 草稿，让作者确认策略后再给 Revision；用户要求两者一起或已授权直接修改时可一次交付。已有确认不重复询问。
6. Revision 只引用实际修订正文。没有原文时说明应修改的章节并给清楚占位；不得编造行号、实验、结果、伦理批准、数据开放或参考文献。

## 结构
整封信按稿件信息、总体回复、编辑意见、各审稿人逐条意见组织；期刊模板优先。姓名、稿号和联系方式只由当前用户提供，缺失时用明确字段占位。
每条采用 Comment → Response → Revision（需要时）→ Location。行号采用最终 clean 或 tracked 版本之一，并说明版本；未知时写“位置待最终排版核对”，不用猜测数值。
小的拼写或符号修订可只写 Response。总体感谢不必重复每条；不得默认所有建议均已采纳。正面评价只回应实际出现的评价。

## 典型模板
以下模板须依据真实状态填写；括号字段不可冒充实际信息。

已完成并有依据：
> Response: Thank you for this suggestion. We have clarified [specific item] in [verified section]. [Answer or key evidence if needed.]
> Revision: [Exact revised passage.]
> Location: [Verified section; line numbers pending if unavailable.]

计划中的修改，明确是草稿：
> Proposed response: We will clarify [specific item] in [section] by [planned action].

有依据的不同意见：
> Response: [Direct answer.] We have retained [choice] because [supported reason]. [Clarification or alternative action, if actually completed.]

总体回复按实际完成情况概括主要修改与未采纳建议；必要时说明逐条依据在后文。不复制模板中的赞扬、完成时或理由来填补事实。

## 最后核对
每个子问题有回答；回应与真实正文一致；数字、术语、引用及位置可核验；新增文献检索核实后再引用。检索学术文献时优先可用的 Consensus，结果不足再用原始来源或网页检索。没有检索工具时标待核验，不编造 DOI。
